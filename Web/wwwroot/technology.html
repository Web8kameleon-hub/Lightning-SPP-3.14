Architecture

A pipeline you can
reason about and control.

Lightning SPP is built as three strict service boundaries — Scan, Process, Print — orchestrated by a single pipeline, with every stage switchable by a named profile.

Processing engines

CLX

Core, efficient processing engine. The default fast path for the lightning profile.

CLI.I

Interactive processing with extended control over intermediate steps.

XCL

Extended processing engine for complex, multi-step workloads.

Hybrid

Combines engines for maximum-quality output, used by the quality Stigma profile.

Clisonic Global AI

AI-assisted enhancement layered on top of the processing context.

Resonance / NanoDecibel

Precision-focused and maximum-quality scan modes, selected per device profile.

Stigma: adaptive pipeline control

Stigma is the control layer that rewrites request parameters across the whole pipeline based on a single profile selection (WWWMMM_STIGMA_LEVEL, resolved in Services/StigmaExecutionProfile.cs). It is not cosmetic — selecting a profile changes which scan mode, processing engine and output quality actually run. Stigma Memory additionally profiles memory usage across runs.

NodeDB Fluid

NodeDB Fluid is a low-overhead hybrid node used as an adaptive sink/bridge for compatibility between nodes and execution profiles — useful when mixing device profiles (desktop, mobile, IoT, cloud) in the same deployment.

Strict service boundaries

IScanService → ScanResult

Real scan implementations (e.g. FastScanService) using SkiaSharp with mode-specific transforms.

IProcessingService → ProcessingResult

Brotli compression plus an ML-context pipeline (e.g. HybridProcessingService).

IPrintService → PrintResult

RealPrintService / StigmaPrintService create .br output artifacts — not physical printer drivers.

LightningPipeline

The orchestrator: license check → profile application → metrics → optional output artifact, for every request.

Runtime and deployment

  • .NET 10, with Native AOT support
  • Docker containers, cross-platform (Windows, Linux, macOS)
  • Invariant globalization for predictable, locale-independent output
  • HTTP API served via HttpListener, with per-IP rate limiting, CORS, and admin bearer-token protected routes
