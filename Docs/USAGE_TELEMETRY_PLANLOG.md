# Lightning SPP — Usage Telemetry Planlog

`declared`: Version 1.1, 2026-11-07. This is a dynamic project constitution: it records direction, dated deliverables, conditions, evidence and decisions. It may change when facts or priorities change; changes must be dated and justified. CI/CD enforces the current contract and blocks overdue work without evidence. Planned behavior is not runtime capability.

## Approved direction

`declared`: Lightning SPP has been live for about two months, as stated by the owner. Workstation benchmark runs are real measurements and remain distinct from production usage history.

`declared`: Preserve usage continuously across process restarts and deployments. Persist detailed usage privately; publish a daily, anonymized aggregate JSON file to Git. Never create placeholder production values or reconstruct unavailable history from unrelated evidence.

`computed`: Customer identity, account state and entitlements are stored through `CustomerStore` in Longo. This does not establish that API usage events are currently stored.

`computed`: `Services/LightningMetrics.cs` holds global pipeline and stage counters in static process memory. Values reset when the process restarts; they are not customer-scoped and do not form a durable daily history.

`unavailable`: Complete two-month request totals, customer-level usage history and daily success rates are unavailable from the inspected in-memory metrics. Retained production logs and edge/proxy analytics must be reconciled before historical claims are made.

## Architecture decisions

| ID | State | Decision |
|---|---|---|
| D01 | declared | Private Longo usage ledger is the detailed source of truth. Process memory is only a cache. |
| D02 | declared | Events are idempotent and append-only; lifetime and UTC-day totals survive restarts and releases. Corrections retain an audit trail. |
| D03 | declared | Authenticated events use verified internal customer/account identity. Anonymous calls remain anonymous; do not infer an owner from IP or request content. |
| D04 | declared | Event fields are limited to event ID, UTC time, route/operation, outcome/status, elapsed time, byte counts, resolved plan/license tier, release/commit identity and sanitized failure category. |
| D05 | declared | Never store request/response bodies, document names or contents, passwords, cookies, authorization headers, Stripe secrets, license keys or raw IP addresses in the usage ledger. |
| D06 | declared | Customer usage is accessible only to that customer and authorized operators. Public Git contains aggregate metrics only, never customer rows or stable customer identifiers. |
| D07 | declared | Daily Git publication is generated by scheduled GitHub Actions with least-privilege write access. Production holds no Git write credential. Publication is idempotent per UTC date. |
| D08 | declared | Missing historical windows remain explicit gaps. Do not infer call counts from uptime, Stripe receipts, workstation benchmarks or current process counters. |
| D09 | declared | Usage is observational until billing semantics are separately reconciled. Do not treat telemetry as billing authority before deduplication, unit definitions and reconciliation are verified. |
| D10 | declared | This Planlog is dynamic. Schedule, scope, state or acceptance changes require a dated Planlog amendment with prior value, new value, reason, decision owner and evidence/review basis. |

## Evidence and lifecycle

`declared`: Use evidence states `measured`, `computed`, `declared`, `unavailable` and `not_implemented`. Distinguish static source review from executed checks. A source declaration or planning document does not prove runtime behavior.

| Label | Required evidence |
|---|---|
| DISCOVERED | Exact repository path and revision found. |
| VERIFIED | Implementation and relevant checks inspected; execution status stated accurately. |
| INTEGRATED | Real service communication or execution demonstrated with traces and failure cases. |
| MISSING | Object not found in a documented search scope; do not generalize beyond that scope. |

`declared`: Follow Discover → Verify → Reuse → Integrate → Validate. Preserve the no-fake rule: no simulated customer records, invented production metrics, random output, silent persistence success or inferred historical values.

## Dynamic amendments

`declared`: Plan dates, phase scope, acceptance conditions and states may change. Preserve the previous value; append an amendment containing date/time with timezone, phase, field, prior value, new value, reason, decision owner and evidence/review reference. Do not erase or silently replace history.

`declared`: CI compares the current machine-readable contract with the base revision. Any change to a phase's date, state, deliverables, acceptance conditions or evidence requirements must have a matching amendment. Deadline extensions therefore remain possible, but undocumented extensions fail the gate. Normal pull-request review remains required.

## CI/CD enforcement

`measured`: `Scripts/planlog-gate.py` was added in commit `b551f101a04bd2be130a56ee40a1b72a9eb3daf5`; `.github/workflows/ci-cd.yml` invokes it in commit `a582320cf7b91e33fe8ce3ddc83d9c81a29b7139`. These are source changes only; the gate has not yet run in CI.

`declared`: The workflow runs the gate before restore/build/tests. It validates the Planlog contract, phase order and dates; checks evidence paths for verified phases; requires amendments for contract changes; and blocks once a target deadline passes without verified evidence. Existing build, test, Docker, release and production-deploy gates still apply.

## JSON publication contract

`declared`: Suggested path: `artifacts/usage/daily/YYYY-MM-DD.json`. Public aggregates may include UTC date/window, schema version, source completeness, service version/commit, route-level call/success/failure counts, byte totals and observed latency summaries. Omit fields without measurements; do not substitute zero.

`declared`: Public JSON must not contain customer names, emails, stable customer IDs, IPs, request payloads, document metadata, secrets or per-customer rows. Private per-customer detail remains in Longo and in the authenticated product view.

`declared`: Daily files are append-only evidence. A correction must be a traceable revision with its reason and source; do not silently rewrite a published result.
